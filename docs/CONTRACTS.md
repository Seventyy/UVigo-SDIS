# V2X contracts (source of truth)

This file is the agreement between the components. If code and this file disagree, one of them is wrong:
fix it, do not guess. To change a contract, edit this file **first** (commit message prefix `contract:`)
and tell the other person before changing behaviour other components depend on.

Owners: RSU `services/rsu/` and `.github/` -> Person A. Simulator `simulator/`, V2X-SERVICE
`services/v2x-service/`, `infra/` -> Person B (Jaime).

## 1. Big picture

```text
Simulator (OBUs) --MQTT--> RSU --SQS v2x-events--> V2X-SERVICE --> DynamoDB
Simulator (OBUs) <--MQTT-- RSU <--HTTP POST /sns-- SNS v2x-alerts <-- V2X-SERVICE
Simulator (OBUs) <--MQTT-- RSU   (local alert, generated by the RSU itself, no cloud involved)
```

## 2. Identifiers and formats

- RSUs: `rsu-1`, `rsu-2`. Ring road segments `S00`..`S11`: `S00`-`S05` belong to `rsu-1`, `S06`-`S11` to `rsu-2`.
  Every event already carries its zone in `location.rsu_id`.
- Vehicles `veh-0001`..`veh-0005`, emergency vehicle `ev-0001`. Events generated by an RSU use
  `source_id` = the RSU id (`rsu-1`) and `source_type` = `rsu`.
- `event_id`: UUIDv4 string. `alert_id`: deterministic, built from the cause event id (section 5).
- Times: ISO 8601 UTC with milliseconds and `Z`, e.g. `2026-11-14T10:15:30.123Z`.
- Schemas: `schema/v2x-event.schema.json` and `schema/v2x-alert.schema.json`. Everything that is sent
  must validate against them.

## 3. MQTT (vehicle <-> RSU)

| Topic | Direction | Payload | QoS | Retain |
| --- | --- | --- | --- | --- |
| `v2x/<rsu_id>/up` | OBU -> RSU | one event JSON | 1 | no |
| `v2x/<rsu_id>/alerts` | RSU -> OBUs | one alert JSON | 1 | no |

- One JSON object per message, UTF-8, no batching. Broker: Mosquitto inside the RSU container, anonymous, no TLS.
- QoS 1 means at-least-once: duplicates are possible, so the RSU deduplicates by `event_id`.
- Mosquitto runs with `max_queued_messages 100000` and `max_inflight_messages 200`. With its defaults
  (1000 queued) the broker silently dropped messages when a 1800-message burst arrived.
- The simulator picks the RSU for each event from `event.location.rsu_id`. It keeps one MQTT connection per RSU,
  publishes to `v2x/<rsu_id>/up` and subscribes to `v2x/<rsu_id>/alerts` on both.
- In MQTT mode the simulator does **not** send events with `source_type: "rsu"` (the RSU makes its own `density`).
- Client ids: simulator `sim-<run_id>-<rsu_id>`, RSU application `rsu-app-<rsu_id>`.
- The simulator writes every alert it receives to `runs/<run_id>/alerts_received.jsonl` as
  `{"received_time": ..., "rsu_id": ..., "alert": {...}}`.

## 4. Events and RSU edge processing

Event schema is unchanged. Optional `trace` object: RSU adds `rsu_received_time` and `rsu_forward_time`,
V2X-SERVICE adds `cloud_received_time` (already does).

| event_type | RSU treatment |
| --- | --- |
| `position` | aggregated into `density`, **not** forwarded individually |
| `brake`, `crash`, `hazard`, `emergency`, `collision_risk` | forwarded to SQS immediately (class `critical`) |
| `density` (generated by the RSU) | forwarded to SQS (class `routine`) |

- Validation: invalid against the event schema -> dropped, counted as `invalid`, never forwarded.
- Deduplication: `event_id` already seen (last 10 000 ids) -> dropped, counted as `duplicate`.
- Density: every `AGG_WINDOW_S` seconds, one event per segment of its zone that had at least one `position`
  in the window. Payload `{"vehicle_count": int, "mean_speed_mps": float, "window_s": float}`.
  New `event_id` (UUIDv4), own `seq` counter per RSU starting at 0.

## 5. Alerts

| alert_type | origin | created by | trigger | severity | alert_id |
| --- | --- | --- | --- | --- | --- |
| `sudden_braking` | cloud | V2X-SERVICE | `brake` with `decel_mps2` >= 4 | 1 (<7), 2 (>=7) | `brake:<event_id>` |
| `local_hard_braking` | rsu | RSU | `brake` with `decel_mps2` >= `LOCAL_BRAKE_DECEL` (4) | 1 (<7), 2 (>=7) | `local-brake:<event_id>` |
| `local_crash` | rsu | RSU | `crash` | 3 | `local-crash:<event_id>` |

- **Local alert**: the RSU publishes it to its own `v2x/<rsu_id>/alerts` as soon as the event arrives, without
  waiting for the uplink or the cloud. The cause event is still forwarded to SQS as usual.
- **Cloud alert path**: V2X-SERVICE stores the alert, publishes it to SNS; both RSUs receive it.
- **Relevance rule** (RSU, for cloud alerts): relay to own vehicles if `location.rsu_id` equals the RSU's id
  **or** `severity >= 2`; otherwise drop it and count it as `alerts_filtered`.
- The RSU deduplicates alerts by `alert_id` (SNS may deliver twice).

## 6. Cloud resources

- **SQS `v2x-events`**: standard queue + dead-letter queue (`maxReceiveCount` 5). Message body = one event JSON,
  exactly as validated. The RSU sends in batches of up to 10 (`send_message_batch`). V2X-SERVICE validates, stores
  idempotently by `event_id` and deletes the message only after a successful write.
- **SNS `v2x-alerts`**: standard topic. V2X-SERVICE publishes `Message` = the alert JSON string (resolves the topic
  ARN by name). Each RSU subscribes itself at start-up with protocol `http` and endpoint
  `http://<PUBLIC_HOST>:<PUBLIC_HTTP_PORT>/sns`. Plain HTTP is allowed (the course staff removed the HTTPS
  requirement by e-mail).
- **`POST /sns` on the RSU**: SNS sends `Content-Type: text/plain`, so read the raw body and parse it with `json.loads`.
  Header `x-amz-sns-message-type: SubscriptionConfirmation` -> `GET` the `SubscribeURL`.
  `Notification` -> the alert is `json.loads(body["Message"])`. Always answer 200 quickly.
- **DynamoDB**: tables `v2x-events`, `v2x-windows`, `v2x-alerts` (unchanged).

## 7. RSU uplink: buffering and retry policy

- Two in-memory FIFO queues: `critical` and `routine`; total size limit `BUFFER_MAX` (5000).
- A sender thread takes up to 10 events (critical first), calls `send_message_batch`, removes only what succeeded.
- On failure or when the uplink is switched off: keep the events, retry with exponential backoff 0.5 s, 1 s, 2 s ...
  up to 30 s. On the first success the backlog is flushed (critical first, oldest first inside a class).
- When the buffer is full: drop the oldest `routine` event; if none is left, drop the oldest `critical` one.
  Every drop is counted as `dropped_overflow`.
- `rsu_forward_time` is set when the event is actually sent, so buffering delay shows up in the latency.

## 8. Hosts and ports

Every RSU runs on its **own EC2 instance** (course requirement), so both use the same ports.

| Component | EC2 instance (tag `Role`) | Published ports | Security group |
| --- | --- | --- | --- |
| `rsu-1` | `rsu-1` | MQTT `1883`, HTTP `8080` | `v2x-rsu-sg` |
| `rsu-2` | `rsu-2` | MQTT `1883`, HTTP `8080` | `v2x-rsu-sg` |
| `v2x-service` | `v2x-service` | HTTP `8080` (dashboard, REST) | `v2x-service-sg` |

Inbound TCP from `0.0.0.0/0` on those ports. Each instance has `/opt/v2x/deploy.sh <image tag>` (created by its
EC2 user data); CI runs it through SSM on the instances found by the `Role` tag. `python infra/aws/bootstrap.py`
creates all of this.

Local development (two RSUs on one laptop): `rsu-1` with `-p 1883:1883 -p 8080:8080`,
`rsu-2` with `-p 1884:1883 -p 8081:8080`.

## 9. RSU HTTP interface (inside the container, port 8080)

- `GET /health` -> `{"ok": true}`
- `GET /stats` -> counters: `received`, `invalid`, `duplicate`, `forwarded`, `buffered`, `dropped_overflow`,
  `local_alerts`, `cloud_alerts_received`, `cloud_alerts_relayed`, `alerts_filtered`, `uplink_up`
- `POST /admin/uplink?up=false|true` -> simulates losing / restoring the connection to AWS (experiments, demo)
- `POST /sns` -> SNS endpoint (section 6)

## 10. Configuration

RSU container environment variables:

| Variable | Meaning | Default |
| --- | --- | --- |
| `RSU_ID` | `rsu-1` or `rsu-2` | required |
| `AWS_DEFAULT_REGION` | AWS region | `us-east-1` |
| `EVENTS_QUEUE` | SQS queue name | `v2x-events` |
| `ALERTS_TOPIC` | SNS topic name | `v2x-alerts` |
| `PUBLIC_HOST` | public IP of the instance (used in the SNS subscription) | read from EC2 metadata |
| `PUBLIC_HTTP_PORT` | published HTTP port | `8080` |
| `AGG_WINDOW_S` | density window | `5` |
| `BUFFER_MAX` | uplink buffer size | `5000` |
| `LOCAL_BRAKE_DECEL` | local brake alert threshold (m/s^2) | `4` |

Simulator flags added for MQTT: `--rsu1 HOST:PORT` (default `localhost:1883`) and
`--rsu2 HOST:PORT` (default `localhost:1884`), used with `--transport mqtt`.
On AWS: `--rsu1 <public IP of rsu-1>:1883 --rsu2 <public IP of rsu-2>:1883`.
